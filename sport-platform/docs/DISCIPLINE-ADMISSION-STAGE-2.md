# Параметры дисциплины и ограничения генерации — этап 2

## Подтверждённые исходные факты
- Старое опубликованное демо: 8 заявок, все участники 2000 г. р.; MEN/WOMEN без возрастных ограничений, общая группа OPEN.
- Интерфейс старого демо не показывает заполненных distanceMeters/stroke/gender/poolLengthMeters.
- EventDisciplineMapper передаёт settingsJson из entity в response без преобразования.
- CreateEventDisciplineForm до этого патча не отправлял settingsJson.
- CreateRegistrationUseCase в присланном коде не проверяет возраст/пол относительно правил дисциплины.
- Категории/возраст уже реализованы в ProtocolCategoryPolicy/ProtocolEligibilityVerifier.

## Что меняется этим патчем
- Параметры плавания в форме создания дисциплины (в DRAFT-мероприятии).
- Необязательный advanced-фильтр allowedCategoryCodes.
- Backend объединяет настройки шаблона с переопределениями верхнего уровня.
- Параметры типов проверяются, gender и фильтр категорий валидируются.
- До генерации проверяется пол снимка против gender дисциплины.
- Категории регламента сужаются по allowedCategoryCodes; неизвестные коды отклоняются.
- Возраст проверяет существующая политика; новый калькулятор возраста не добавляется.
- Ограничение подключено к одиночной и сессионной генерации.
- В новые снимки генерации дисциплины добавляются использованные disciplineSettings.
- Предварительная таблица заявок учитывает явный фильтр категорий дисциплины.

## Важные ограничения
- Подача, повторная подача и подтверждение заявок этим патчем не изменяются.
  Несоответствующая подтверждённая заявка блокирует генерацию, а не исключается молча.
- Это не полный аудит всех путей регистрации и всех способов ручного назначения на дорожку.
- Дистанция/стиль относятся к дисциплине, заявки выбираются по disciplineId.
  Патч не сравнивает заявочные времена с дистанциями других дисциплин и не проверяет внешние нормативы.
- Поле stroke хранит непустой код; UI предлагает пять известных вариантов.
  Backend не добавляет отдельный справочник стилей для всех видов спорта.
- Параметры не делаются обязательными задним числом для старых дисциплин без metadata.
- Старые snapshots не переписываются, миграции и записи БД установщиком не выполняются.
- Порядок сессий/дисциплин и scheduledAt остаются отдельной задачей проверки.
- Выбор групп по человекочитаемым названиям ещё не реализован: временно коды через запятую.

## Следующий порядок
1. Компиляция и выбранные unit-тесты, frontend-тесты/сборка, архитектурные проверки.
2. HTTP/DB интеграция обоих путей генерации, включая отказ без замены старого протокола.
3. Создание отдельного DRAFT-демо с новой версией регламента и категориями нужных годов рождения.
4. Настройка 10 дисциплин, тестовых заявок и двух сессий.
5. Проверка групп, дорожек, NT, порядка и расписания.
6. Ранняя проверка допуска на подаче/повторной подаче/подтверждении, единый безопасный контракт.
7. UX выбора категорий по названиям вместо ручного ввода кодов.

Старое финализированное демо и его участников не изменять ради проверки нового пути.
