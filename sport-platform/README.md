# Sport Platform

MVP-платформа для управления спортивными мероприятиями, дисциплинами,
заявками участников, платежами, стартовыми списками и публикацией результатов.

## Возможности MVP

- Управление спортивными событиями и дисциплинами
- Регистрация участников на дисциплины
- Проверка и подтверждение заявок
- Платежи: ручной сценарий и интеграция с YooKassa webhook
- Создание соревновательных единиц: заплывов, матчей, групп и финалов
- Назначение подтверждённых заявок в соревновательные единицы
- Внесение результатов, пересчёт мест и публикация
- Публичный каталог событий и опубликованные результаты без авторизации
- JWT-аутентификация и RBAC

## Настройка окружения

Создайте локальный файл `.env` по примеру `.env.example`:

```powershell
Copy-Item .env.example .env
```

JWT-ключ должен быть стандартным Base64, содержащим не менее 32 байт после
декодирования. Длина строки сама по себе не доказывает соответствие этому требованию.

Создайте отдельный случайный ключ для каждой среды и сохраните его в защищённой
конфигурации стенда. Не используйте значения из истории Git или тестов.
Не генерируйте новый ключ при каждом перезапуске: смена ключа делает ранее
выданные токены недействительными.

Для локальной smoke-проверки команда генерации без вывода ключа приведена в
[инструкции JWT](docs/security/jwt-first-start.md).
Для постоянного стенда сгенерируйте ключ один раз и сохраните его безопасно.

`.env.example` содержит пустое поле `JWT_SECRET`, а не рабочий ключ.
`.env` не должен попадать в Git. Maven/Spring Boot может не загружать его
автоматически: передайте `JWT_SECRET` в окружение процесса backend или в
environment variables run configuration IntelliJ. Не выводите ключ в терминал
и не вставляйте его в команды, сохраняемые в истории.

## Запуск инфраструктуры

Запустите PostgreSQL, Redis и Kafka:

```powershell
docker compose up -d
```

Проверьте состояние контейнеров:

```powershell
docker compose ps
```

## Запуск backend

Из корня проекта:

```powershell
# JWT_SECRET уже передан через защищённое окружение процесса.
mvn spring-boot:run
```

Backend будет доступен по адресу:

```text
http://localhost:8080
```

Проверка health endpoint:

```text
GET http://localhost:8080/actuator/health
```

## Запуск frontend

В отдельном терминале:

```powershell
cd frontend
npm install
npm run dev
```

Frontend обычно доступен по адресу:

```text
http://localhost:5173
```

## Тесты

Запуск полного backend suite:

```powershell
mvn test
```

Запуск security unit test:

```powershell
mvn test "-Dtest=JwtAuthenticationFilterTest"
```

Production build frontend:

```powershell
cd frontend
npm run build
```

## Публичный API

Публичные GET endpoints не требуют JWT:

```text
GET /api/v1/public/events
GET /api/v1/public/events/{publicSlug}
GET /api/v1/public/events/{eventId}/disciplines/{eventDisciplineId}/results
```

Публичные результаты включают только опубликованные соревновательные единицы.

## Основной MVP flow

```text
Организатор создаёт событие
→ создаёт дисциплину
→ открывает регистрацию
→ участник подаёт заявку
→ организатор подтверждает заявку
→ создаётся payment
→ организатор создаёт заплыв / матч / группу / финал
→ подтверждённая заявка назначается в unit
→ оператор вносит результат
→ система пересчитывает места
→ организатор публикует unit
→ гость видит опубликованные результаты без авторизации
```

## Безопасность

- JWT secret передаётся только через `JWT_SECRET`
- `.env` исключён из Git
- Actuator health доступен публично без инфраструктурных details
- Другие Actuator endpoints доступны только роли `PLATFORM_ADMIN`
- Некорректные JWT без roles claim отклоняются как невалидные

## Первый запуск: администратор и ключ JWT

Для чистой базы перед первым запуском backend передайте в окружение процесса:

| Переменная | Что передать |
|---|---|
| `APP_BOOTSTRAP_ADMIN_ENABLED` | `true` только для первоначальной настройки; по умолчанию bootstrap выключен. |
| `APP_BOOTSTRAP_ADMIN_EMAIL` | Адрес первого администратора (`app.bootstrap.admin.email`). |
| `APP_BOOTSTRAP_ADMIN_PASSWORD` | Уникальный пароль первого администратора (`app.bootstrap.admin.password`). |
| `JWT_SECRET` | Отдельный случайный ключ стенда: 32 случайных байта, закодированные в Base64. Не используйте ключ из истории Git или из другой среды. |

Значения передавайте через окружение процесса или настройки секретов при развёртывании. `.env.example` — шаблон, не источник рабочих секретов. Не сохраняйте заполненные значения в Git.

После запуска войдите через обычную форму входа и проверьте роль администратора платформы. Когда вход подтверждён, установите `APP_BOOTSTRAP_ADMIN_ENABLED=false`, уберите `APP_BOOTSTRAP_ADMIN_EMAIL` и `APP_BOOTSTRAP_ADMIN_PASSWORD` из окружения штатного запуска и перезапустите backend с bootstrap, выключенным в новой конфигурации. `JWT_SECRET` оставьте в настройках стенда: он нужен для подписи и проверки токенов. Пароль администратора повторным запуском не сбрасывается.

Подробности и ограничения: [первый администратор](docs/security/bootstrap-admin.md).
Проверку чистой установки выполняйте только на отдельной тестовой базе, не на
существующей демобазе или production.
